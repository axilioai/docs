A **run** is one execution of a workflow. Each entry in `runs` creates one run
with its own phone session.

## Run it now

<Tabs sync={false}>
  <Tab title="Dashboard">
    1. Open [**Workflows**](https://app.axilio.ai/dashboard).
    2. Select the workflow.
    3. Click **Run**.
  </Tab>

  <Tab title="CLI">
    The current CLI release cannot start a run against API `0.72`. Use the
    dashboard, an SDK, or the REST API until the CLI is updated.
  </Tab>

  <Tab title="Python SDK">
    ```python
    from axilio import RunConfig

    result = client.runs.create(
        workflow_id=workflow_id,
        runs=[RunConfig(variables=[{}])],
        start_timeout_seconds=300,
    )
    run_id = result.run_ids[0]
    ```
  </Tab>

  <Tab title="Go SDK">
    ```go
    result, err := api.Runs.Create(ctx, &platformgo.RunCreateRequest{
        WorkflowID: workflowID,
        Runs: []*platformgo.RunConfig{
            {Variables: []map[string]any{{}}},
        },
        StartTimeoutSeconds: platformgo.Int64(300),
    })
    if err != nil {
        log.Fatal(err)
    }
    runID := result.RunIDs[0]
    ```
  </Tab>

  <Tab title="REST API">
    ```bash
    curl --request POST \
      --url "https://api.axilio.ai/api/v1/workflows/$WORKFLOW_ID/runs" \
      --header "X-Axilio-Api-Key: $AXILIO_API_KEY" \
      --header "Content-Type: application/json" \
      --data '{
        "runs": [{"variables": [{}]}],
        "start_timeout_seconds": 300
      }'
    ```

    [API reference: Start a run](/api-reference/rest/runs/start-a-run)
  </Tab>
</Tabs>

`start_timeout_seconds` controls how long a queued run may wait for a phone. It
must be between 60 and 86,400 seconds and defaults to 300.

<Note>
  The current public dashboard, CLI, SDK, and REST contracts queue runs
  immediately. They do not expose a future start-time or recurring schedule.
</Note>

## Run many at once

Create one entry per run. Each run gets its own phone and
[session observability surfaces](/observability).

<Tabs sync={false}>
  <Tab title="Dashboard">
    1. Open [**Workflows**](https://app.axilio.ai/dashboard).
    2. Select the workflow and click **Run**.
    3. Choose **Start Now** and set **Number of Runs** to `3`.
    4. Choose how Axilio should allocate phones, then click **Start Run**.

    The dashboard accepts between 1 and 1,000 runs in one request.
  </Tab>

  <Tab title="CLI">
    The current CLI release cannot start parallel runs against API `0.72`. Use
    an SDK or the REST API until the CLI is updated.
  </Tab>

  <Tab title="Python SDK">
    ```python
    result = client.runs.create(
        workflow_id=workflow_id,
        runs=[RunConfig(variables=[{}]) for _ in range(3)],
    )
    print(result.run_ids)
    ```
  </Tab>

  <Tab title="Go SDK">
    ```go
    result, err := api.Runs.Create(ctx, &platformgo.RunCreateRequest{
        WorkflowID: workflowID,
        Runs: []*platformgo.RunConfig{
            {Variables: []map[string]any{{}}},
            {Variables: []map[string]any{{}}},
            {Variables: []map[string]any{{}}},
        },
    })
    if err != nil {
        log.Fatal(err)
    }
    fmt.Println(result.RunIDs)
    ```
  </Tab>

  <Tab title="REST API">
    ```bash
    curl --request POST \
      --url "https://api.axilio.ai/api/v1/workflows/$WORKFLOW_ID/runs" \
      --header "X-Axilio-Api-Key: $AXILIO_API_KEY" \
      --header "Content-Type: application/json" \
      --data '{
        "runs": [
          {"variables": [{}]},
          {"variables": [{}]},
          {"variables": [{}]}
        ]
      }'
    ```

    [API reference: Start a run](/api-reference/rest/runs/start-a-run)
  </Tab>
</Tabs>
