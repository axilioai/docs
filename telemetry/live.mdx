Live telemetry gives you progressive visibility into a phone session. It uses
the same span-and-log frame envelope that you can [retrieve later](/telemetry/retrieve).
The stream is Server-Sent Events (`text/event-stream`): it starts with the
retained trace so far, then follows new frames as they happen, and closes when
the session ends.

## Follow a session

<Tabs sync={false}>
  <Tab title="Dashboard">
    1. Open [**Sessions**](https://app.axilio.ai/dashboard/axilio/sessions).
    2. Select an active session.
    3. Click **Observability**.

    **Timeline** pairs span starts and ends as work progresses. **Console**
    displays output and error logs. Select a timeline row to inspect its
    currently available details.

    When the session ends, the Dashboard replaces the live view of the trace
    with retained history.
  </Tab>

  <Tab title="CLI">
    Print the retained prefix, then follow new frames until the session ends:

    ```bash
    axilio sessions trace sess_123 --follow
    ```

    Follow a workflow run from its queue state through its final outcome:

    ```bash
    axilio runs watch run_123
    ```

    Add `-o json` for newline-delimited JSON. `sessions trace --follow` emits
    one frame per line and finishes with:

    ```json
    {"trace_end":true,"session_id":"...","frames":0,"session_ended":true,"sdk_call_costs":{},"inference_costs":{}}
    ```

    `frames` is the number of distinct delivered frames. `runs watch -o json`
    ends with:

    ```json
    {"watch_end":true,"run_id":"...","status":"completed","error_message":null}
    ```

    `runs watch` exits with 0 for completed, 1 for failed, and 7 for cancelled
    or locally interrupted work. The CLI handles resume, replay
    deduplication, and retained reconciliation.
  </Tab>

  <Tab title="Python SDK">
    Follow a session by its ID with your client's API key:

    ```python
    from axilio.platform import Client

    client = Client()
    telemetry = client.telemetry("sess_123")

    for frame in telemetry.tail(open_timeout=10):
        print(frame)
    ```

    The loop gets the trace so far, then live frames, and ends on its own when
    the session ends. If your process allocated the phone, you can pass the
    allocation's `telemetry_url` as the second argument instead. The helper
    resumes after a drop with `Last-Event-ID`. Use `telemetry.logs(live=True)`
    when you only need logs.

    `open_timeout` covers opening the stream. Iteration can wait for the next
    frame while the session remains active.

    The high-level helper is synchronous. A rejected credential raises
    `UnauthorizedError`, an unknown session raises `SessionNotFoundError`, a
    session with Telemetry off raises `TelemetryOffError`, and an exhausted
    reconnect sequence raises a retryable `ConnectionError`.
  </Tab>

  <Tab title="Go SDK">
    Open the stream with the session's URL and your API key:

    ```go
    package main

    import (
        "context"
        "errors"
        "fmt"
        "io"
        "log"
        "net/http"
        "os"

        "github.com/axilioai/platform-go/drivers/telemetry"
    )

    func main() {
        ctx := context.Background()
        url := telemetry.StreamURL("https://api.axilio.ai/api/v1", "sess_123")
        key := http.Header{"X-Axilio-Api-Key": {os.Getenv("AXILIO_API_KEY")}}

        stream, err := telemetry.Tail(ctx, url, telemetry.WithHeader(key))
        if err != nil {
            log.Fatal(err)
        }
        defer stream.Close()

        for {
            frame, err := stream.Next(ctx)
            if errors.Is(err, io.EOF) {
                break
            }
            if err != nil {
                log.Fatal(err)
            }
            fmt.Printf("%+v\n", frame)
        }
    }
    ```

    Import the helper from
    `github.com/axilioai/platform-go/drivers/telemetry`. An allocation's
    `telemetry_url` works too, with no header. The stream reopens with
    `Last-Event-ID` after a drop.

    `Stream.Next(ctx)` returns the next frame and `io.EOF` once the session is
    over; `Ended()` then reports `true`. `Close()` stops the reader. Context
    cancellation or deadline returns the context error.

    `*telemetry.Error` uses the codes `unauthorized`, `not_found`,
    `telemetry_off`, `connection`, and `closed`. `Next` and `Close` can run
    from different goroutines, but multiple concurrent `Next` calls are not
    supported.
  </Tab>

  <Tab title="REST (SSE)">
    Read the stream with any Server-Sent Events client. With your API key:

    <WindowsCurlNote />

    ```bash
    curl --no-buffer \
      --url https://api.axilio.ai/api/v1/realtime/sessions/sess_123/events \
      --header "X-Axilio-Api-Key: $AXILIO_API_KEY"
    ```

    Or use the session's `telemetry_url`, which carries a read-only token for
    this one session. It comes back from `POST /phones:allocate` and from every
    `GET /phones/sessions/{session_id}`, so a browser `EventSource` can open it
    without headers.

    REST API reference:

    - [**Stream a session's telemetry**](/api-reference/rest/phones/stream-a-sessions-telemetry): `GET /realtime/sessions/{session_id}/events`
  </Tab>
</Tabs>

## Protect the URL

`telemetry_url` contains a bearer credential in its query string.

- Treat the entire URL as a secret.
- Do not put it in application logs, analytics, screenshots, or referrer data.
- Share it only with the process that reads this session's telemetry.
- Discard the URL when you no longer need it.

The token is scoped to one session and is read-only. It expires about an hour
after it is issued; read the session again for a fresh URL. Server clients can
send the API key header instead.

## Read events

Each event carries one frame:

```text
id: 1761240000000-0
event: span
data: {"kind":"span","phase":"start","span_type":"sdk_call",...}

```

- `id` is the event's cursor. Treat it as an opaque string.
- `event` is the frame kind, such as `span` or `log`.
- `data` is the frame JSON. See the [Frame reference](/telemetry/frames).

Frames replayed from the retained record carry no `id`. After the replay, an
event with only an `id` (no data) carries the cursor the replay ended at.
Comment lines (starting with `:`) arrive every 15 seconds while the stream is
idle; ignore them.

Accept new fields and unfamiliar `span_type` or `log_type` values, and ignore
events with an unfamiliar name.

## Resume after a drop

Reconnect with the `Last-Event-ID` header set to the last `id` you received.
`EventSource` does this on its own. While the cursor is inside the live window,
the stream continues right after it with no gap. If the cursor is older than
the live window, the stream replays the retained record first, the same as a
new reader.

The stream deduplicates within one connection. A reconnect that falls back to
the replay can deliver frames you already have, so deduplicate on
`(trace_id, span_id, phase)` for spans and on content for logs.

## When the session ends

The stream sends what is left and closes. Reconnecting after that with your
last cursor returns `204 No Content`, which tells `EventSource` to stop. A
reader that connects after the session ended gets the retained record, then
the stream closes.

| Status | Meaning |
| --- | --- |
| `200` | The stream. |
| `204` | The session is over and nothing is left after your cursor. Stop. |
| `401` | The credential was rejected. Read the session again for a fresh `telemetry_url`. |
| `404` | No such session in your organization. |
| `409` | The session was started with Telemetry off. Nothing is streamed or stored. |
| `503` | The server is restarting. Retry with backoff. |

## Set delivery expectations

- Live delivery is best-effort. A frame dropped at publish can be missing from
  the live stream; the retained record is the reconciliation source.
- A live frame does not prove that an identical record was retained.
- Do not assume every started span receives a live end frame.
- The live and retained paths are not exactly-once services.

For retry classification, gap recovery, and terminal outcomes, follow
[Reliability and troubleshooting](/telemetry/reliability).
