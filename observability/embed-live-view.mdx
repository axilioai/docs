When you allocate a phone, the response includes a `live_view_url`: a hosted
page showing the phone's live screen. It's fully interactive — taps, swipes,
and typing reach the phone — and it works opened in a browser tab or embedded
in your own app as an iframe.

```python
device = client.phones.allocate(phone_type="ANDROID")
print(device.live_view_url)
```

## Embed it

```html
<iframe
  src="{live_view_url}"
  allow="autoplay; clipboard-read; clipboard-write"
  style="width: 100%; height: 100%; border: 0;"
></iframe>
```

That's the whole integration. The stream starts muted, so it renders without a
play button under every browser autoplay policy.

The page and its connections use exactly two origins. If your app sets a
`Content-Security-Policy`, allow them:

```
frame-src https://app.axilio.ai;
connect-src https://connect.axilio.ai wss://connect.axilio.ai;
```

### Keyboard input

Browsers deliver keystrokes to an iframe only while it has focus, and Safari
grants focus to a cross-origin iframe only from a user action. Call
`iframe.focus()` inside a click handler on your page:

```js
iframe.addEventListener("click", () => iframe.focus())
```

Pointer input (tap, swipe) works without this.

## Appearance

By default the page renders just the phone screen on a transparent background,
so it fills your iframe and blends into your page. Size the iframe to a portrait
aspect ratio (the phone is taller than it is wide) and it looks at home in your
UI. Two query params tune the look:

| Param | Values | Default |
| --- | --- | --- |
| `bg` | `transparent`, `dark`, `light`, or a hex color (e.g. `1e293b` or `#1e293b`) | `transparent` |
| `frame` | `device` to wrap the screen in a phone mockup | screen only |

```html
<!-- blends into your page (default) -->
<iframe src="{live_view_url}" style="width: 100%; height: 100%; border: 0;"></iframe>

<!-- dark surround behind the screen -->
<iframe src="{live_view_url}?bg=dark"></iframe>

<!-- phone mockup on a custom background -->
<iframe src="{live_view_url}?frame=device&bg=1e293b"></iframe>
```

`bg` sets the color shown around the screen (the letterbox when the video's
aspect ratio doesn't match your iframe) and behind the connecting/ended states.
The page never shows Axilio branding, so it fits a white-labeled product.

## Treat the URL as a secret

`live_view_url` carries a signed token scoped to this one session. Anyone who
has the URL can watch — and, unless the session is view-only — drive the phone
until the session ends. Handle it like a credential:

- Don't log it or send it to analytics.
- Prefer `view_only` or `auth: "org"` (below) when the URL travels beyond
  people you trust.
- There is no rotation: to kill a leaked URL, end the session with
  `deallocate`. Every live view URL stops working the moment its session ends.

## Options

Set live view behavior per session when you allocate:

```python
device = client.phones.allocate(
    phone_type="ANDROID",
    live_view={"view_only": True},
)
```

| Option | Effect |
| --- | --- |
| `auth: "token"` (default) | The URL carries its own credential. No sign-in; embeds anywhere. |
| `auth: "org"` | The URL carries no credential. Viewers must sign in to Axilio and belong to your organization. A leaked URL is useless to outsiders. |
| `view_only: true` | Watch-only. Input never reaches the phone — enforced on our side, not just hidden in the page. |
| `disabled: true` | No live view exists for this session; `live_view_url` is omitted. |

<Note>
  `auth: "org"` is for sharing inside your team — open it in a tab or link it
  in Slack. It isn't suited to embedding for your own end users: the sign-in
  inside a third-party iframe depends on the viewer's browser cookie settings.
  For embeds, use the default token mode.
</Note>

## One viewer at a time

A session streams to one viewer at a time. If a second viewer opens the live
view — in your app or in the Axilio dashboard — the newest viewer takes over
and the previous one is disconnected.
