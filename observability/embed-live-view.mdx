When an allocation includes `live_view_url`, the URL opens a hosted page showing
the phone's live screen. It accepts taps, swipes, and keyboard input unless you
configure it as view-only. Open it in a browser tab or embed it in your own app
as an iframe.

<Tabs sync={false}>
  <Tab title="CLI">
    The current CLI release cannot start sessions against API `0.72`. Use an SDK
    or REST to obtain the iframe URL until it is updated.
  </Tab>

  <Tab title="Python SDK">
    ```python
    device = client.phones.allocate(phone_type="android", pool="dedicated")
    print(device.live_view_url)
    ```
  </Tab>

  <Tab title="Go SDK">
    ```go
    device, err := api.Phones.Allocate(ctx, &platformgo.PhoneAllocateRequest{
        PhoneType: platformgo.PhoneAllocateRequestPhoneTypeAndroid,
        Pool:      platformgo.PhoneAllocateRequestPoolDedicated.Ptr(),
    })
    if err != nil {
        log.Fatal(err)
    }
    if device.LiveViewURL != nil {
        fmt.Println(*device.LiveViewURL)
    }
    ```
  </Tab>

  <Tab title="REST API">
    ```bash
    curl --request POST \
      --url https://api.axilio.ai/api/v1/phones:allocate \
      --header "X-Axilio-Api-Key: $AXILIO_API_KEY" \
      --header "Content-Type: application/json" \
      --data '{
        "phone_type": "android",
        "pool": "dedicated"
      }'
    ```

    [API reference: Allocate a phone](/api-reference/rest/phones/allocate-a-phone)

    Use the response's `live_view_url` as the iframe `src`.
  </Tab>
</Tabs>

Keep the allocation active while the iframe is mounted. Deallocate the returned
`phone_id` when you remove the viewer.

## Embed it

```html
<iframe
  src="{live_view_url}"
  allow="autoplay; clipboard-read; clipboard-write"
  style="width: 100%; height: 100%; border: 0;"
></iframe>
```

That's the whole integration. The stream starts muted, which usually lets it
render without a play button under modern browser autoplay policies.

If your app sets a `Content-Security-Policy`, allow the live-view page as a
frame source:

```
frame-src https://app.axilio.ai;
```

The cross-origin live-view page governs its own network connections. Your
parent page does not need to add Axilio's WebSocket origin to `connect-src` for
the iframe to connect.

### Keyboard input

Browsers deliver keystrokes to an iframe only while it has focus. Ask the viewer
to click or tap inside the phone screen before typing. Do not rely on a click
listener on the parent `<iframe>` element: clicks inside a cross-origin iframe
do not bubble to its parent page.

Pointer input works as soon as the viewer interacts with the embedded screen.

## Appearance

By default the page renders just the phone screen on a transparent background,
so it fills your iframe and blends into your page. Size the iframe to a portrait
aspect ratio (the phone is taller than it is wide) and it looks at home in your
UI. Two query params tune the look:

| Param | Values | Default |
| --- | --- | --- |
| `bg` | `transparent`, `dark`, `light`, or a 3/6-digit hex color such as `1e293b` | `transparent` |
| `frame` | `device` to wrap the screen in a phone mockup | screen only |

```html
<!-- blends into your page (default) -->
<iframe src="{live_view_url}" style="width: 100%; height: 100%; border: 0;"></iframe>

<!-- dark surround behind the screen -->
<iframe src="{live_view_url}?bg=dark"></iframe>

<!-- phone mockup on a custom background -->
<iframe src="{live_view_url}?frame=device&bg=1e293b"></iframe>
```

`bg` sets the color shown around the screen (the letterbox when the video's
aspect ratio doesn't match your iframe) and behind the connecting/ended states.
The page never shows Axilio branding, so it fits a white-labeled product.

## Treat the URL as a secret

In token mode, `live_view_url` carries a signed credential scoped to one
session. Anyone who has the URL can watch and, unless the view is read-only,
drive the phone while access remains valid. Handle it like a credential:

- Don't log it or send it to analytics.
- Prefer `view_only` or `auth: "org"` (below) when the URL travels beyond
  people you trust.
- There is no standalone rotation. If a URL leaks, deallocate the session to
  prevent new connections and close any viewer your application already opened.

## Options

Set live view behavior per session when you allocate:

<Tabs sync={false}>
  <Tab title="Python SDK">
    ```python
    device = client.phones.allocate(
        phone_type="android",
        pool="dedicated",
        live_view={"auth": "token", "view_only": True},
    )
    ```
  </Tab>

  <Tab title="Go SDK">
    ```go
    device, err := api.Phones.Allocate(ctx, &platformgo.PhoneAllocateRequest{
        PhoneType: platformgo.PhoneAllocateRequestPhoneTypeAndroid,
        Pool:      platformgo.PhoneAllocateRequestPoolDedicated.Ptr(),
        LiveView: &platformgo.PhoneLiveViewOptions{
            Auth:     platformgo.PhoneLiveViewOptionsAuthToken.Ptr(),
            ViewOnly: platformgo.Bool(true),
        },
    })
    if err != nil {
        log.Fatal(err)
    }
    if device.LiveViewURL == nil {
        if _, cleanupErr := api.Phones.Deallocate(ctx, &platformgo.PhonesDeallocateRequest{
            PhoneID: device.PhoneID,
        }); cleanupErr != nil {
            log.Printf("release phone: %v", cleanupErr)
        }
        log.Fatal("allocation returned no live view URL")
    }
    fmt.Println(*device.LiveViewURL)
    ```
  </Tab>

  <Tab title="REST API">
    ```bash
    curl --request POST \
      --url https://api.axilio.ai/api/v1/phones:allocate \
      --header "X-Axilio-Api-Key: $AXILIO_API_KEY" \
      --header "Content-Type: application/json" \
      --data '{
        "phone_type": "android",
        "pool": "dedicated",
        "live_view": {
          "auth": "token",
          "view_only": true
        }
      }'
    ```

    [API reference: Allocate a phone](/api-reference/rest/phones/allocate-a-phone)
  </Tab>
</Tabs>

The view-only setting lasts for that allocation. Keep it active while the
iframe is mounted, then deallocate the phone.

The CLI and dashboard allocation flows do not currently expose live-view
access options. Use an SDK or the REST API when you need to change them.

| Setting | Values | Default | Effect |
| --- | --- | --- | --- |
| `auth` | `"token"`, `"org"` | `"token"` | `"token"` puts a session-scoped credential in the URL. `"org"` requires an Axilio sign-in and membership in your organization. |
| `view_only` | `false`, `true` | `false` | `false` allows interaction. `true` makes the view watch-only, enforced on our side rather than only hidden in the page. |
| `disabled` | `false`, `true` | `false` | `true` prevents Axilio from creating a live view and omits `live_view_url`. |

You can omit `live_view` to use all three defaults. If `disabled` is `true`,
the other settings have no effect because no live view is created.

<Note>
  `auth: "org"` is for sharing inside your team — open it in a tab or link it
  in Slack. It isn't suited to embedding for your own end users: the sign-in
  inside a third-party iframe depends on the viewer's browser cookie settings.
  For embeds, use the default token mode.
</Note>

## Multiple viewers

More than one viewer can watch the same session. An interactive viewer can send
input to the phone. Inputs from multiple interactive viewers can interleave;
this screen path does not assign one viewer exclusive control. Make observers
view-only when one viewer should control the phone.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| The iframe is blocked | Allow `https://app.axilio.ai` in the parent page's `frame-src` policy. |
| Typing has no effect | Click or tap inside the phone screen before typing. |
| The view is read-only | Check whether the allocation enabled `view_only`. |
| The view no longer connects | Confirm that the phone session is still active. |
