Screen recording is on by default, but it is configurable per phone allocation
and per workflow. When recording is enabled, Axilio writes a video of the phone
screen and makes it available after the session ends and processing completes.

In [**Sessions**](https://app.axilio.ai/dashboard/axilio/sessions),
select a session. The session inspector places the video beside its execution
timeline and logs, so you can seek from a frame to the matching point in the
recording.

## Configure recording

Disable recording for one directly allocated phone:

```python
allocation = client.phones.allocate(
    phone_type="android",
    phone_id="ph_123",
    recording=False,
)
```

Disable recording for future runs of a workflow:

```python
client.workflows.update(
    workflow_id,
    recording=False,
)
```

When recording is disabled, Axilio does not write a recording or rolling
thumbnail for that session. Your organization's data-retention policy can also
prevent recordings from being created or make older recordings unavailable.

## Look up a recording with Python

Recordings are keyed by `session_id`, so the same operation works for workflow
runs and directly allocated sessions:

```python
recording = client.phones.session_recording(session_id)

if recording.status == "ready":
    print(recording.url)
elif recording.status == "pending":
    print("The recording is not ready")
elif recording.status == "expired":
    print("The recording is outside the retention window")
```

The current statuses are:

| Status | Meaning |
| --- | --- |
| `ready` | `url` contains a time-limited playback link. |
| `pending` | No recording object is available. The session may still be active, its upload may still be processing, or recording may have been disabled. |
| `expired` | The recording is outside the organization's retention window. |

Only `ready` includes a URL. If you know recording was enabled and the session
has completed, fetch the lookup again while its upload processes. `pending`
alone does not promise that a recording will appear.

## Look up a recording with Go

```go
recording, err := api.Phones.SessionRecording(
    ctx,
    &platformgo.PhonesSessionRecordingRequest{SessionID: sessionID},
)
if err != nil {
    return err
}

if recording.Status == platformgo.PhoneSessionRecordingResponseStatusReady &&
    recording.URL != nil {
    fmt.Println(*recording.URL)
}
```

## Download the MP4 with Python

The `ready` URL points to the MP4 for a limited time. Look it up again instead
of persisting an expired URL.

```python
import httpx

recording = client.phones.session_recording(session_id)
if recording.status != "ready" or not recording.url:
    raise RuntimeError(f"recording is {recording.status}")

with httpx.stream("GET", recording.url) as response:
    response.raise_for_status()
    with open("session.mp4", "wb") as output:
        for chunk in response.iter_bytes():
            output.write(chunk)
```

<Note>
  The CLI does not currently have a recording lookup or download command. Use
  the dashboard, Python or Go SDK, or the REST recording operation.
</Note>
