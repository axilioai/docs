Screen recording is off by default. Turn it on for a session, an agent, or an
ad hoc run, and Axilio records the phone's screen and makes the MP4 available
after the session ends and its upload finishes.

Recordings are keyed by `session_id`, so the same lookup works for runs and
directly allocated sessions. A run's session ID is its run ID.

## Configure recording

Recording is an allocation-time setting. Changing an agent affects its future
runs, not sessions that already started.

<Tabs sync={false}>
  <Tab title="Dashboard">
    Record one directly allocated session:

    1. Open [**Sessions**](https://app.axilio.ai/dashboard/axilio/sessions).
    2. Click **Allocate A Phone**.
    3. Expand **advanced configuration**.
    4. Turn **recording** on.
    5. Click **Allocate**.

    Record an ad hoc run: on
    [**Run a task**](https://app.axilio.ai/dashboard/axilio/agents/run), turn
    on **Record the screen** before you start the run.

    A run that was not recorded shows **Recording was off** in the session
    viewer. For a saved agent's run, members also see **Record future runs**,
    which turns recording on for the agent.
  </Tab>

  <Tab title="CLI">
    Record an agent's runs when you create it:

    ```bash
    axilio agents create checkout-flow --code checkout.py --recording=true
    ```

    Confirm its current setting with `axilio agents get <agent-id>`. The CLI
    does not expose a recording flag on `sessions start` or an update command
    for an existing agent.
  </Tab>

  <Tab title="Python SDK">
    Record one direct allocation:

    ```python
    from axilio.platform import Client

    client = Client()
    allocation = client.phones.allocate(
        phone_type="android",
        phone_id="ph_123",
        recording=True,
    )
    ```

    To record an agent's future runs, use the REST API until the SDK adds
    agents in its next release.
  </Tab>

  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "log"
        "os"

        platformgo "github.com/axilioai/platform-go"
        "github.com/axilioai/platform-go/client"
        "github.com/axilioai/platform-go/option"
    )

    func main() {
        ctx := context.Background()
        api := client.NewClient(option.WithAPIKey(os.Getenv("AXILIO_API_KEY")))
        recordingOn := true

        allocation, err := api.Phones.Allocate(ctx, &platformgo.PhoneAllocateRequest{
            PhoneType: platformgo.PhoneAllocateRequestPhoneTypeAndroid,
            PhoneID:   platformgo.String("ph_123"),
            Recording: &recordingOn,
        })
        if err != nil {
            log.Fatal(err)
        }
        defer func() {
            if _, err := api.Phones.Deallocate(
                context.Background(),
                &platformgo.PhonesDeallocateRequest{PhoneID: allocation.PhoneID},
            ); err != nil {
                log.Printf("release phone: %v", err)
            }
        }()
    }
    ```

    The allocation setting applies only to `allocation.SessionID`. To record
    an agent's future runs, use the REST API until the SDK adds agents in its
    next release.
  </Tab>

  <Tab title="REST API">
    REST API References:

    - [**Allocate a phone**](/api-reference/rest/phones/allocate-a-phone): `POST /phones:allocate`
    - [**Update an agent**](/api-reference/rest/agents/update-an-agent): `PATCH /agents/{agent_id}`
    - [**Start a run**](/api-reference/rest/runs/start-a-run): `POST /runs`

    Record one direct allocation:

    <WindowsCurlNote />

    ```bash
    curl --silent --show-error --fail-with-body \
      --request POST \
      --url https://api.axilio.ai/api/v1/phones:allocate \
      --header "X-Axilio-Api-Key: $AXILIO_API_KEY" \
      --header "Content-Type: application/json" \
      --data '{
        "phone_type": "android",
        "phone_id": "ph_123",
        "recording": true
      }'
    ```

    Record future runs of an existing agent:

    ```bash
    curl --silent --show-error --fail-with-body \
      --request PATCH \
      --url https://api.axilio.ai/api/v1/agents/agent_123 \
      --header "X-Axilio-Api-Key: $AXILIO_API_KEY" \
      --header "Content-Type: application/json" \
      --data '{"recording_enabled": true}'
    ```

    Record one ad hoc run by sending `"recording_enabled": true` on
    `POST /runs`.
  </Tab>
</Tabs>

When recording is off, Axilio does not write a recording for that session.
Your organization's data-retention policy can also prevent recordings from
being created or make older recordings unavailable.

## Replay or download a recording

<Tabs sync={false}>
  <Tab title="Dashboard">
    1. Open [**Sessions**](https://app.axilio.ai/dashboard/axilio/sessions).
    2. Change the status filter if the completed session is not visible.
    3. Select the session.
    4. Play the recording on the left side of the **SESSION VIEWER**.

    The **Timeline** and **Console** stay synchronized with playback. Select a
    timeline bar or console entry to seek to that point. The viewer shows a
    processing, expired, or recording-off state when no playable URL exists.
  </Tab>

  <Tab title="CLI">
    Look up the recording's status and, when it is ready, a time-limited URL:

    ```bash
    axilio sessions recording sess_123
    axilio sessions recording sess_123 -o json
    ```

    The lookup exits 0 for `ready`, `pending`, `expired`, and `off`, so a
    script can branch on the `status` field.

    Download the MP4. `--wait` polls while the recording is still processing
    (default timeout 10 minutes, exit status 5 when it elapses), and `--force`
    overwrites an existing file:

    ```bash
    axilio sessions recording sess_123 --wait --out session.mp4
    ```

    The file is written atomically, so an interrupted download never leaves a
    partial MP4 behind. A pending recording is refused without `--wait`; an
    expired recording cannot be downloaded and exits with not-found status 4.
    Run the lookup again instead of persisting a URL: returned URLs expire.
  </Tab>

  <Tab title="Python SDK">
    ```python
    from pathlib import Path

    import httpx

    from axilio.platform import Client

    client = Client()
    recording = client.phones.session_recording("sess_123")

    if recording.status != "ready" or not recording.url:
        raise RuntimeError(f"recording is {recording.status}")

    with httpx.stream("GET", recording.url, follow_redirects=True) as response:
        response.raise_for_status()
        with Path("session.mp4").open("wb") as output:
            for chunk in response.iter_bytes():
                output.write(chunk)
    ```
  </Tab>

  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "errors"
        "io"
        "log"
        "net/http"
        "os"

        platformgo "github.com/axilioai/platform-go"
        "github.com/axilioai/platform-go/client"
        "github.com/axilioai/platform-go/option"
    )

    func main() {
        ctx := context.Background()
        api := client.NewClient(option.WithAPIKey(os.Getenv("AXILIO_API_KEY")))

        recording, err := api.Phones.SessionRecording(
            ctx,
            &platformgo.PhonesSessionRecordingRequest{SessionID: "sess_123"},
        )
        if err != nil {
            log.Fatal(err)
        }
        if recording.Status != platformgo.PhoneSessionRecordingResponseStatusReady ||
            recording.URL == nil {
            log.Fatal(errors.New("recording is not ready"))
        }

        response, err := http.Get(*recording.URL)
        if err != nil {
            log.Fatal(err)
        }
        defer response.Body.Close()
        if response.StatusCode < 200 || response.StatusCode >= 300 {
            log.Fatalf("download recording: %s", response.Status)
        }

        output, err := os.Create("session.mp4")
        if err != nil {
            log.Fatal(err)
        }
        defer output.Close()

        if _, err := io.Copy(output, response.Body); err != nil {
            log.Fatal(err)
        }
    }
    ```
  </Tab>

  <Tab title="REST API">
    REST API References:

    - [**Get a session recording**](/api-reference/rest/phones/get-a-session-recording): `GET /phones/sessions/{session_id}/recording`

    <WindowsCurlNote />

    ```bash
    RECORDING=$(curl --silent --show-error --fail-with-body \
      --request GET \
      --url https://api.axilio.ai/api/v1/phones/sessions/sess_123/recording \
      --header "X-Axilio-Api-Key: $AXILIO_API_KEY")

    STATUS=$(printf '%s' "$RECORDING" | jq -r '.status')
    if [ "$STATUS" != "ready" ]; then
      printf 'recording is %s\n' "$STATUS" >&2
      exit 1
    fi

    RECORDING_URL=$(printf '%s' "$RECORDING" | jq -r '.url')
    curl --silent --show-error --fail --location \
      "$RECORDING_URL" \
      --output session.mp4
    ```
  </Tab>
</Tabs>

## Recording states

| Status | Meaning |
| --- | --- |
| `ready` | `url` contains a playback link that stays valid for one hour. |
| `pending` | The session recorded, but the recording is not available yet. The session may still be active, or its upload may still be processing. |
| `expired` | The recording is outside the organization's retention window. |
| `off` | The session was not recorded. No recording will appear. |

Only `ready` includes a URL. For `pending`, fetch the lookup again while the
upload processes, or let `axilio sessions recording <session-id> --wait` poll
for you.
