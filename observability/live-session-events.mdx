When an allocation response includes `telemetry_url`, connect to it with a
WebSocket client to receive recent and newly published event frames for that
session.

The stream uses an Axilio-specific JSON protocol. It is not OpenTelemetry or
OTLP, and it is not the same response format as the archived session events
API.

<Warning>
  This preview is intended for live diagnostic interfaces. The protocol is not
  yet a versioned integration contract. Do not build production automation that
  depends on fixed fields, ordering, or complete delivery.
</Warning>

## Connect to the stream

Allocate a phone, pass its `telemetry_url` to a WebSocket client, and deallocate
the phone when the stream closes:

<Tabs sync={false}>
  <Tab title="CLI">
    The current CLI release cannot start sessions against API `0.72`, and it
    does not include a live-event consumer. Use an SDK or the REST example until
    the CLI is updated.
  </Tab>

  <Tab title="Python SDK">
    Install a WebSocket client with `pip install websockets`, then run:

    ```python
    import asyncio
    import json

    import websockets
    from axilio.platform import Client

    client = Client()

    async def main():
        device = client.phones.allocate(phone_type="android")
        try:
            if not device.telemetry_url:
                raise RuntimeError("allocation returned no telemetry URL")

            async with websockets.connect(device.telemetry_url) as ws:
                async for message in ws:
                    frame = json.loads(message)
                    print(frame)
        finally:
            client.phones.deallocate(device.phone_id)

    asyncio.run(main())
    ```
  </Tab>

  <Tab title="Go SDK">
    Install a WebSocket client with
    `go get github.com/coder/websocket@v1.8.15`. This fragment runs inside a
    function after you construct the authenticated `api` client. It uses
    `context`, `errors`, `fmt`, `log`, `os`, `os/signal`, `time`,
    `platformgo`, and `github.com/coder/websocket`:

    ```go
    ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt)
    defer stop()

    err := func() error {
        device, err := api.Phones.Allocate(ctx, &platformgo.PhoneAllocateRequest{
            PhoneType: platformgo.PhoneAllocateRequestPhoneTypeAndroid,
        })
        if err != nil {
            return err
        }
        defer func() {
            cleanupCtx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
            defer cancel()
            if _, err := api.Phones.Deallocate(cleanupCtx, &platformgo.PhonesDeallocateRequest{
                PhoneID: device.PhoneID,
            }); err != nil {
                log.Printf("release phone: %v", err)
            }
        }()

        if device.TelemetryURL == nil {
            return errors.New("allocation returned no telemetry URL")
        }

        conn, _, err := websocket.Dial(ctx, *device.TelemetryURL, nil)
        if err != nil {
            return err
        }
        defer conn.Close(websocket.StatusNormalClosure, "client closed")

        for {
            _, message, err := conn.Read(ctx)
            if err != nil {
                return err
            }
            fmt.Println(string(message))
        }
    }()
    if err != nil && !errors.Is(err, context.Canceled) {
        log.Fatal(err)
    }
    ```
  </Tab>

  <Tab title="REST API">
    Install `jq` and `websocat`, then run this as a shell script. The exit trap
    releases the phone:

    ```bash
    set -euo pipefail

    ALLOCATION=$(curl --silent --show-error --fail-with-body --request POST \
      --url https://api.axilio.ai/api/v1/phones:allocate \
      --header "X-Axilio-Api-Key: $AXILIO_API_KEY" \
      --header "Content-Type: application/json" \
      --data '{"phone_type":"android"}')

    PHONE_ID=$(printf '%s' "$ALLOCATION" | jq -r '.phone_id')
    TELEMETRY_URL=$(printf '%s' "$ALLOCATION" | jq -r '.telemetry_url // empty')

    cleanup() {
      curl --silent --show-error --fail-with-body --request POST \
        --url "https://api.axilio.ai/api/v1/phones/$PHONE_ID:deallocate" \
        --header "X-Axilio-Api-Key: $AXILIO_API_KEY" >/dev/null
    }
    trap cleanup EXIT

    if test -z "$TELEMETRY_URL"; then
      echo "allocation returned no telemetry URL" >&2
      exit 1
    fi

    websocat "$TELEMETRY_URL"
    ```
  </Tab>
</Tabs>

The Axilio SDKs return the signed URL but do not wrap the event WebSocket.

`telemetry_url` contains the credential needed for the connection. Do not add
an API-key header to the WebSocket handshake.

<Note>
  The dashboard consumes this stream to render live session activity, but it
  does not expose the raw WebSocket as an integration. Open an active session
  in **Sessions** when you only need to inspect the activity yourself.
</Note>

## Understand the stream

- **Read-only:** do not send application messages on the socket.
- **Recent replay:** a new connection first receives the recent frames still
  available for that session, then follows newly published frames.
- **Best-effort delivery:** do not use the stream as an audit log or billing
  source.
- **Reconnection:** reconnecting can replay frames your client already handled.
  Deduplicate work by the identifiers present in the payload when appropriate.
- **Session lifecycle:** deallocation prevents new connections. Close your
  existing socket when your application ends the session.

<Warning>
  Fields and frame variants can evolve, and compatibility traffic can include
  older event objects. Consumers should ignore unknown fields and payload
  variants. Do not build a durable or compliance-sensitive ingestion pipeline
  against this stream.
</Warning>

## Reconcile native lifecycle frames

Native span lifecycle frames describe either the start or end of an operation.
Use `trace_id` and `span_id` to associate related frames, and use `phase` to
distinguish `start` from `end`. The end frame settles the operation with its end
time and status when those fields are available.

Native log frames carry a log type, time, severity, and body. They can also carry
correlation identifiers. Your consumer must tolerate a log without a span
identifier and a lifecycle end frame arriving before its start frame.

Compatibility event objects use a different envelope and might not include any
of those fields. Treat their top-level `type` as an opaque discriminator and
ignore body shapes your diagnostic viewer does not recognize.

Do not assume that every live frame has an archived equivalent or that every
archived event appears in the bounded live replay window.

## Use the archive after the session

The [session events API](/observability/session-events) is the supported way to
retrieve the archived events currently available for a session. It uses a
different schema and delivery path, and records can take time to appear after
an operation completes.

## Handle the URL safely

<Warning>
  `telemetry_url` is a session-scoped bearer credential. Do not log it, persist
  it in analytics, expose it in a browser error, or share it with an untrusted
  party.
</Warning>
