Telemetry is the structured execution record for a phone session. Its frames
include in-flight and completed operations, inference work, file activity, and
output logs. The live stream and the retained
[frame archive](/observability/frames) use the same envelope.

Use live Telemetry while a session is active. Use the frame archive after it
ends or whenever you need the authoritative retained trace.

## Follow a live session

<Tabs sync={false}>
  <Tab title="Dashboard">
    1. Open [**Sessions**](https://app.axilio.ai/dashboard/axilio/sessions).
    2. Select an active session.
    3. Click **Observability**.

    The **Timeline** updates with spans while **Console** shows output and error
    logs. Select a timeline bar to inspect its details. The live phone remains
    visible on the left.

    If the session ends while the page is open, the Dashboard refreshes the
    subject and replaces the live feed with its retained trace. A session
    started with Telemetry off shows **Telemetry disabled for this session**.
  </Tab>

  <Tab title="CLI">
    Print the retained prefix, then follow new frames until the session ends:

    ```bash
    axilio sessions trace sess_123 --follow
    ```

    Follow a workflow run from its queue state through its final outcome:

    ```bash
    axilio runs watch run_123
    ```

    Both commands reconnect through the archive if the live connection is
    unavailable. With `-o json`, they emit newline-delimited JSON: one frame
    per line followed by a final `trace_end` or `watch_end` object.
  </Tab>

  <Tab title="Python SDK">
    Mint a fresh URL for any active session in your organization, then attach
    the high-level helper:

    ```python
    from axilio.platform import Client

    client = Client()
    session_id = "sess_123"

    grant = client.phones.session_telemetry_token(session_id)
    telemetry = client.telemetry(session_id, grant.telemetry_url)

    for frame in telemetry.tail():
        print(frame)
    ```

    The helper reconnects automatically, resumes from its last cursor, and
    deduplicates replayed frames. The loop ends after it yields the session's
    terminal frame. Use `telemetry.logs(live=True)` when you only need logs.

    If your process allocated the phone, you can pass
    `allocation.telemetry_url` instead of minting another URL.
  </Tab>

  <Tab title="Go SDK">
    ```go
    package main

    import (
        "context"
        "errors"
        "fmt"
        "io"
        "log"
        "os"

        platformgo "github.com/axilioai/platform-go"
        "github.com/axilioai/platform-go/client"
        "github.com/axilioai/platform-go/drivers/telemetry"
        "github.com/axilioai/platform-go/option"
    )

    func main() {
        ctx := context.Background()
        api := client.NewClient(option.WithAPIKey(os.Getenv("AXILIO_API_KEY")))
        sessionID := "sess_123"

        grant, err := api.Phones.SessionTelemetryToken(
            ctx,
            &platformgo.PhonesSessionTelemetryTokenRequest{SessionID: sessionID},
        )
        if err != nil {
            log.Fatal(err)
        }

        view := telemetry.NewSession(
            api,
            sessionID,
            telemetry.WithTelemetryURL(grant.TelemetryURL),
        )
        stream, err := view.Tail(ctx)
        if err != nil {
            log.Fatal(err)
        }
        defer stream.Close()

        for {
            frame, err := stream.Next(ctx)
            if errors.Is(err, io.EOF) {
                break
            }
            if err != nil {
                log.Fatal(err)
            }
            fmt.Printf("%+v\n", frame)
        }

        if stream.Gapped() {
            fmt.Println("Live replay gap detected; refetch the archived trace")
        }
    }
    ```

    Import the helper from
    `github.com/axilioai/platform-go/drivers/telemetry`. It reconnects and
    resumes from its latest cursor. Delivery is at least once, so deduplicate
    replayed frames if your consumer requires exactly-once presentation. When
    `stream.Gapped()` is true, call `view.Trace` to rebuild from the archive.
  </Tab>

  <Tab title="REST API">
    REST API References:

    - [**Mint a Telemetry stream URL**](/api-reference/rest/phones/mint-a-telemetry-stream-url): `POST /phones/sessions/{session_id}/telemetry-token`

    Mint a read-only WebSocket URL, then attach a WebSocket client. This example
    uses `websocat`:

    ```bash
    TELEMETRY_URL=$(curl --silent --show-error --fail-with-body \
      --request POST \
      --url https://api.axilio.ai/api/v1/phones/sessions/sess_123/telemetry-token \
      --header "X-Axilio-Api-Key: $AXILIO_API_KEY" \
      | jq -r '.telemetry_url')

    websocat "$TELEMETRY_URL"
    ```

    The token operation is organization-scoped and refuses inactive sessions.
    If you use a raw client, implement the
    [reconnect and resume contract](/api-reference/dcp/reconnect).
  </Tab>
</Tabs>

## Stream behavior

- **Treat the URL as a secret.** The URL embeds a session-scoped credential, so
  you can connect without additional headers.
- **The stream is read-only.** The stream ignores any messages you send.
- **If you join late, you receive the recent retained window** before following
  new frames.
- **A message can contain one frame or an array of frames.** Support both forms.
- **Delivery is at least once.** A reconnect can replay frames.
- **Unknown frame kinds and fields are additive.** Preserve or render them
  generically instead of failing the stream.
- **The URL dies with the session.** The retained archive remains available
  only for your organization's Telemetry-retention window.

<Note>
  The Python helper deduplicates replayed frames. The Go helper resumes but
  exposes possible duplicates and reports an expired replay window through
  `Gapped()`. The CLI reconciles the archive and live stream for you.
</Note>
