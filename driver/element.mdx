Python `screen.find_text()` and `screen.find_all_text()` return `Element`
values; Go returns the corresponding `mobile.Element`. An element is data from
one [observed screen](/driver/screen): what was recognized and where. It has no
actions. To act on something, use a [locator](/driver/locator), or pass
`element.center` to a coordinate action.

<Tabs sync={false}>
  <Tab title="Python SDK">
    ```python
    element = driver.observe().find_text("Sign in")
    if element is not None:
        print(element.center, element.confidence)
        driver.tap(element.center)
    ```
  </Tab>

  <Tab title="Go SDK">
    ```go
    screen, err := driver.Observe()
    if err != nil {
        log.Fatal(err)
    }
    element := screen.FindText("Sign in", false)
    if element != nil {
        fmt.Println(element.Center, element.Confidence)
        if err := driver.Tap(element.Center); err != nil {
            log.Fatal(err)
        }
    }
    ```
  </Tab>
</Tabs>

An element's position is from the moment the screen was observed. If the screen
may have changed since, tap with a locator instead, which finds the target again
at the moment it acts.

The CLI prints the same element data in table or JSON output. There is no REST
element resource.

## Fields

| Python | Go | Description |
| --- | --- | --- |
| `element.center` | `element.Center` | Tap point at the element's center. |
| `element.bbox` | `element.BBox` | Bounding box in screen pixels. |
| `element.text` | `element.Text` | Recognized text, when present. |
| `element.confidence` | `element.Confidence` | Match confidence from `0` to `1`. |
| `element.source` | `element.Source` | `ocr` when the returned result carries recognized text; otherwise `vlm`. |
