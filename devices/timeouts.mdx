A **session** is a temporary control lease on one of your dedicated phones. It
is separate from the phone rental: ending a session stops control and makes the
phone available for another session, but it does not erase the phone, sign out
of its apps, or end your rental.

## What `client.session()` does

`client.session()` is the Python SDK helper that manages the complete session
lifecycle. When you use it with `with`, it:

1. Claims the selected phone and creates a session.
2. Creates a [`MobileDriver`](/driver/reference) configured for that session.
3. Opens the control connection when you send the first driver command.
4. Closes the driver and releases the session when the block exits—even if your
   code raises an error.

<Tabs sync={false}>
  <Tab title="CLI">
    Start the session, control its phone, then stop it explicitly:

    ```bash
    eval "$(axilio sessions start --phone-id ph_123 --export)"

    # The session is active and phone commands control it.
    axilio phone tap --query "the Settings icon"

    # Stop the session when you finish.
    axilio sessions stop "$AXILIO_SESSION" --yes
    ```
  </Tab>

  <Tab title="Python SDK">
    The context manager releases the session automatically:

    ```python
    with client.session("android", phone_id="ph_123") as driver:
        # The session is active and driver controls the phone.
        driver.find_text("Settings").tap()

    # The driver is closed and the session is released.
    # The dedicated phone and its app state remain yours.
    ```
  </Tab>

  <Tab title="Go SDK">
    Allocate the phone and defer both driver and session cleanup:

    ```go
    allocation, err := api.Phones.Allocate(ctx, &platformgo.PhoneAllocateRequest{
        PhoneType: platformgo.PhoneAllocateRequestPhoneTypeAndroid,
        PhoneID:   platformgo.String("ph_123"),
    })
    if err != nil {
        log.Fatal(err)
    }
    defer api.Phones.Deallocate(ctx, &platformgo.PhonesDeallocateRequest{
        PhoneID: allocation.PhoneID,
    })

    if allocation.ControlURL == nil {
        log.Fatal("allocation returned no control URL")
    }
    driver := mobile.ConnectRemote(*allocation.ControlURL)
    defer driver.Close()

    settings, err := driver.Find("the Settings icon")
    if err != nil {
        log.Fatal(err)
    }
    if err := settings.Tap(); err != nil {
        log.Fatal(err)
    }
    ```
  </Tab>
</Tabs>

Entering the `with` block allocates the phone and gives you the `driver`. The
driver opens its control connection lazily when you send the first command, such
as `observe()`, `find()`, or `tap()`.

<Note>
  The CLI's `sessions start` and `sessions stop` commands and the Go SDK's
  `Allocate` and `Deallocate` methods manage the same underlying session
  lifecycle. `client.session()` packages those steps into one Python context
  manager.
</Note>

## Connection timeout is not session duration

`open_timeout` limits how long the SDK can spend opening the control WebSocket.
That includes connecting to Axilio's control service and completing the
WebSocket handshake. The SDK opens this connection when you send the first
driver command, and uses the same timeout if it needs to reconnect later.

This timeout does not wait for Android or an app to finish loading. After the
WebSocket is open, it does not limit how long a driver command can run, close an
idle connection, or set the session duration. The default is 10 seconds:

<Tabs sync={false}>
  <Tab title="CLI">
    The CLI does not currently expose a separate control-connection timeout.
    Start the session, then let the first phone command establish the connection:

    ```bash
    eval "$(axilio sessions start --phone-id ph_123 --export)"
    axilio phone observe
    axilio sessions stop "$AXILIO_SESSION" --yes
    ```
  </Tab>

  <Tab title="Python SDK">
    ```python
    with client.session(
        "android",
        phone_id="ph_123",
        open_timeout=20,
    ) as driver:
        driver.observe()
    ```
  </Tab>

  <Tab title="Go SDK">
    `WithOpenTimeout` applies when the first driver command opens the control
    socket:

    ```go
    driver := mobile.ConnectRemote(
        *allocation.ControlURL,
        mobile.WithOpenTimeout(20*time.Second),
    )
    defer driver.Close()

    if _, err := driver.Observe(); err != nil {
        log.Fatal(err)
    }
    ```
  </Tab>
</Tabs>

## When a session ends

A session can end in three ways:

- **Your code exits the `with` block.** `client.session()` closes the driver and
  releases the session automatically.
- **An optional idle timeout expires.** This applies when an idle timeout was
  configured during allocation.
- **The one-hour maximum is reached.** Axilio enforces this server-side limit as
  a final safety net.

If a timeout ends the session while your code is still running, subsequent
driver commands fail because the control lease is no longer active.

## Manual allocation and cleanup

If you [allocate a phone yourself](/devices/allocate), call `deallocate` when you
finish so it is available for another session. Use `client.session()` when you
want Python to manage that cleanup automatically.

## Dedicated sessions have no device-time charge

Your flat rental covers the dedicated phone around the clock. Starting or
holding a session does not add device-time charges. Vision calls can still incur
separate usage charges. [More on billing](/billing/overview).
