A session starts when Axilio allocates a phone. The common customer-visible
boundaries are manual release, an optional idle timeout, and the platform's
maximum session duration. Axilio can also close a session when its phone
becomes unavailable.

## Idle timeout

`ttl.idle_timeout_seconds` closes a session after that many seconds without a
live user connection. A connected control, live-view, or Telemetry viewer keeps
the session active; after the last viewer disconnects, the idle clock resumes.
A session that was never connected is idle from allocation time.

Omit the value, or pass a nonpositive value, for no idle timeout. Positive
values are clamped to 1–3,600 seconds. A session without an idle timeout still
ends at the one-hour platform cap.

<Tabs sync={false}>
  <Tab title="Dashboard">
    Open [**Sessions**](https://app.axilio.ai/dashboard/axilio/sessions), click
    **Allocate A Phone**, and enter **idle timeout (seconds)**. Leave it blank
    for no idle timeout.
  </Tab>

  <Tab title="Python SDK">
    ```python
    from axilio import PhoneSessionTtlOptions

    allocation = client.phones.allocate(
        phone_type="android",
        phone_id="ph_123",
        ttl=PhoneSessionTtlOptions(idle_timeout_seconds=300),
    )
    ```
  </Tab>

  <Tab title="Go SDK">
    ```go
    allocation, err := api.Phones.Allocate(ctx, &platformgo.PhoneAllocateRequest{
        PhoneType: platformgo.PhoneAllocateRequestPhoneTypeAndroid,
        PhoneID:   platformgo.String("ph_123"),
        TTL: &platformgo.PhoneSessionTTLOptions{
            IdleTimeoutSeconds: platformgo.Int64(300),
        },
    })
    if err != nil {
        log.Fatal(err)
    }
    defer func() {
        if _, err := api.Phones.Deallocate(ctx, &platformgo.PhonesDeallocateRequest{
            PhoneID: allocation.PhoneID,
        }); err != nil {
            log.Printf("release phone: %v", err)
        }
    }()
    ```
  </Tab>

The CLI does not currently expose the idle-timeout option. A CLI-started
session remains active until you stop it or the maximum duration is reached.

## Connection timeout is different

Python's `open_timeout` controls how long the SDK waits to connect to the
allocated phone. It does not set the session lifetime, wait for an app screen,
or change a command deadline:

```python
with client.session("android", phone_id="ph_123", open_timeout=20) as driver:
    print(driver.observe())
```

## Release reliably

Use `client.session()` when Python owns the whole lifetime. For direct
allocations, put deallocation in `finally` or `defer`. With the CLI, run
`axilio sessions stop <session-id> --yes`.

Closing a Dashboard tab does not release the phone. End the session with
**Release** or **Deallocate**. Ending a session frees its control lease; it does
not erase the dedicated phone's apps or state and does not end its rental.
