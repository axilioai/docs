A session starts when Axilio allocates a phone. It ends when you release the
phone, an idle timeout fires, or the platform's maximum session duration is
reached.

## Inspect sessions

<Tabs sync={false}>
  <Tab title="Dashboard">
    Open [**Sessions**](https://app.axilio.ai/dashboard) to filter active and
    completed sessions. Open a row for its phone, source, workflow, recording,
    files, live view, and Telemetry.
  </Tab>

  <Tab title="CLI">
    ```bash
    axilio sessions list --remote
    axilio sessions list --history
    axilio sessions get sess_123
    ```
  </Tab>

  <Tab title="Python SDK">
    ```python
    sessions = client.phones.list_sessions(limit=20)
    session = client.phones.get_session("sess_123")

    print(session.status, session.phone_id, session.recording_status)
    ```
  </Tab>

  <Tab title="Go SDK">
    ```go
    sessions, err := api.Phones.ListSessions(ctx, &platformgo.PhonesListSessionsRequest{
        Limit: platformgo.Int64(20),
    })
    if err != nil {
        log.Fatal(err)
    }

    session, err := api.Phones.GetSession(ctx, &platformgo.PhonesGetSessionRequest{
        SessionID: "sess_123",
    })
    ```
  </Tab>

  <Tab title="REST API">
    Use `GET /api/v1/phones/sessions` for the filtered session table and
    `GET /api/v1/phones/sessions/{session_id}` for one session.
  </Tab>
</Tabs>

## Idle timeout

`ttl.idle_timeout_seconds` closes a session after that many seconds without a
user connection. Omit it for no idle timeout. Explicit values are clamped to
1–3,600 seconds. A session without an idle timeout still ends at the one-hour
platform cap.

<Tabs sync={false}>
  <Tab title="Dashboard">
    Enter **idle timeout (seconds)** when you allocate the phone. Leave it blank
    for no idle timeout.
  </Tab>

  <Tab title="Python SDK">
    ```python
    from axilio import PhoneSessionTtlOptions

    allocation = client.phones.allocate(
        phone_type="android",
        ttl=PhoneSessionTtlOptions(idle_timeout_seconds=300),
    )
    ```
  </Tab>

  <Tab title="Go SDK">
    ```go
    allocation, err := api.Phones.Allocate(ctx, &platformgo.PhoneAllocateRequest{
        PhoneType: platformgo.PhoneAllocateRequestPhoneTypeAndroid,
        TTL: &platformgo.PhoneSessionTTLOptions{
            IdleTimeoutSeconds: platformgo.Int64(300),
        },
    })
    ```
  </Tab>

  <Tab title="REST API">
    ```json
    {
      "phone_type": "android",
      "ttl": {
        "idle_timeout_seconds": 300
      }
    }
    ```
  </Tab>
</Tabs>

The CLI does not currently expose the idle-timeout option. A CLI-started
session remains active until you stop it or the maximum duration is reached.

## Connection timeout is different

Python's `open_timeout` controls how long the SDK waits to connect to the
allocated phone. It does not set the session lifetime:

```python
with client.session("android", open_timeout=20) as driver:
    print(driver.observe())
```

## Release reliably

Use `client.session()` when Python owns the whole lifetime. For direct
allocations, put deallocation in `finally` or `defer`. With the CLI, run
`axilio sessions stop <session-id> --yes`.
