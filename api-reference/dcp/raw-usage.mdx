You can drive a phone without the SDK: allocate a phone, open its `control_url`,
and send [DCP](/api-reference/dcp/overview) frames. This is the same socket the
SDK uses — here you speak to it directly.

The examples use Python's `websockets` library, but nothing is Python-specific.
Any WebSocket client works.

## Before you start

- **An API key** — create one in the [dashboard](https://app.axilio.ai/dashboard).
  See [Authentication](/authentication).
- **A dedicated phone ID** — choose an idle phone in **Phones** or run
  `axilio phones list`.
- **A WebSocket client.** For the examples: `pip install axilio websockets`.

## 1. Get a phone and its control URL

Allocate a phone through the [REST API](/api-reference/overview) or the SDK. The
allocation returns a `control_url` — a WebSocket scoped to this one session:

```python
from axilio.platform import Client

client = Client()

device = client.phones.allocate(phone_type="android", phone_id="ph_123")
control_url = device.control_url
```

<Note>
  The `control_url` is self-contained: its credential is embedded, so you
  connect with no extra headers. Pass it directly to your WebSocket client.
  Never put it in logs, shell history, tickets, or chat, and do not cache it
  across sessions. It stops working when the session ends.
</Note>

## 2. Open the socket and handshake

Send [`Protocol.handshake`](/api-reference/dcp/reference#protocol-handshake)
first. It returns the phone's protocol version, device descriptor, and the exact
set of methods it supports — gate your code on that instead of assuming:

```python
import asyncio
import json

import websockets


async def drive(control_url):
    async with websockets.connect(control_url) as ws:
        # Each command carries an id; the response echoes it.
        await ws.send(json.dumps({"id": 1, "method": "Protocol.handshake", "params": {}}))
        hello = json.loads(await ws.recv())

        caps = hello["result"]["capabilities"]
        device = hello["result"]["device"]
        print("screen:", device["screen_width"], "x", device["screen_height"])
        print("supports:", caps)

asyncio.run(drive(device.control_url))
```

## 3. Send a command

Commands are `{ "id", "method", "params" }`; the phone replies with
`{ "id", "result" }` on success or `{ "id", "error" }` on failure. Tap a pixel:

```python
await ws.send(json.dumps({
    "id": 2,
    "method": "Touch.tap",
    "params": {
        "x": 540,
        "y": 1180,
        "idempotencyKey": "<unique-logical-command-id>",
    },
}))
reply = json.loads(await ws.recv())
if "error" in reply:
    raise RuntimeError(reply["error"]["message"])
```

## 4. Read the screen

`Screen.observe` returns the on-screen text and icons with their bounding
boxes — enough to decide where to tap next:

```python
await ws.send(json.dumps({"id": 3, "method": "Screen.observe", "params": {}}))
screen = json.loads(await ws.recv())["result"]

for item in screen["texts"]:
    print(item["text"], item["bbox"])
```

## Correlating replies

Responses can arrive in any order, so match a reply to its command by `id`
instead of assuming the next frame is the answer. A frame with no `id` is a
notification, not a response. A small pattern: keep an outstanding-id map,
increment a counter per command, and resolve each reply against it. The
[SDK](/driver/overview) does exactly this for you.

The `idempotencyKey` is separate from the request `id`. Generate one UUID per
logical `Touch.*` or `Keyboard.*` command. Reuse that key only if you must
resend the same command after a dropped connection. See
[Reconnect and resume](/api-reference/dcp/reconnect).
