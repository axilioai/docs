This page covers what stays stable, what can change, and how you'll hear about
anything that changes or goes away.

## Versioning

The REST API is versioned in the URL path. Everything on these pages lives
under:

```
https://api.axilio.ai/api/v1
```

`/api/v1` is a stability boundary. Within it:

- **Non-breaking changes ship without notice.** New endpoints, new optional
  request fields, new response fields, new enum values, and new headers can
  appear at any time. Write your client so extra fields it doesn't recognize
  are ignored, not errors.
- **Breaking changes are listed on a dated changes page.** When a release
  renames or removes a field, parameter, path or webhook field in `/api/v1`,
  a changes page lists every old name with its replacement, for example
  [October 2026](/api-reference/api-changes-2026-10). Upgrade your SDK and CLI
  with that release.

The [OpenAPI spec](https://api.axilio.ai/openapi.json) is regenerated with
every release and carries the current API version in `info.version`. If you
generate a client, generate it from there.

## Deprecation

When an endpoint or field is deprecated ahead of its removal, rather than
changed in a release, you hear about it three ways, well before anything stops
working:

1. **In the spec and on these pages.** The operation is marked deprecated in
   the OpenAPI spec (`deprecated: true`) and badged on its reference page,
   with a pointer to the replacement.
2. **On the wire.** Responses from a deprecated endpoint carry a
   `Deprecation` header, and once a removal date is set, a `Sunset` header
   with that date (RFC 8594). Log these in your client and you will never be
   surprised.
3. **With a real migration window.** A deprecated endpoint keeps working for
   at least **90 days** after the `Sunset` header first appears, and we
   contact organizations that are still calling it before it goes away.

Nothing is removed quietly: every removal is either deprecated first or listed
on a changes page.

## Rate limits

Every caller gets a per-minute request budget, keyed by API key (or by IP for
unauthenticated requests). Each response tells you where you stand:

| Header | Meaning |
|---|---|
| `RateLimit-Limit` | Your budget for the current window (requests per minute). |
| `RateLimit-Remaining` | Requests left in the window. |
| `RateLimit-Reset` | Seconds until the window resets. |

Past the budget, requests return `429 Too Many Requests` with a `Retry-After`
header (seconds). Back off for that long and retry; the response body is the
standard [error shape](/reference/errors).

The default budget is generous for normal use, including fleet-scale work: one
`runs` call fans a workflow across many phones, so driving thousands of phones
does not mean thousands of API calls. If you're hitting the limit with a
legitimate workload, [contact us](https://axilio.ai/contact).

## What to do as a client

- Ignore unknown response fields and headers instead of failing on them.
- Watch for `Deprecation` and `Sunset` headers in responses and surface them
  in your logs.
- Honor `Retry-After` on `429`s rather than retrying immediately.
- Regenerate clients from the [live spec](https://api.axilio.ai/openapi.json),
  not from a saved copy.
