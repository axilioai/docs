Choose the UI element that a natural-language query describes from a list of
elements you already have. You send the candidates, and Argus answers with one
of your element `id` values as `element_id`, or `found: false`. It never
answers with a point, so you act on the element itself.

## Why elements and screenshots are separate operations

Screenshot grounding and element grounding take different inputs and give
different answers. A screenshot locate reads pixels and returns a box. An
element locate reads structured elements and returns an element ID. Keeping
them as separate operations gives each one a request and response that fit it
exactly.

The element operation doesn't care where your elements came from. A browser
DOM, the results of [Screenshots: detect](/api-reference/argus/screenshots-detect),
or any other UI tree all map onto the same shape: an `id`, a `role`, a `name`,
an optional `value`, optional pixel `bounds`, and an optional `platform` object
of native attributes, which Argus passes to the model as given.

## Request

- **`query`** describes the target, such as `"the Sign in button"`. Up to 2,000
  characters.
- **`elements`** holds 1 to 2,000 candidates. Each `id` must be unique in the
  request; a duplicate is a validation error. An `id` is at most 256
  characters, a `role` at most 64, a `name` or `value` at most 1,024, and a
  `platform` object at most 4 KiB as JSON.
- **`image`** is an optional base64 PNG or JPEG screenshot. When you send one,
  give `bounds` in that screenshot's pixel space.
- **`model`** is an optional vision-language model from
  [Models: list](/api-reference/argus/list-models). Omit it to use the default.

```json
{
  "query": "the Sign in button",
  "elements": [
    {"id": "12", "role": "textbox", "name": "Email", "value": ""},
    {"id": "13", "role": "textbox", "name": "Password"},
    {
      "id": "14",
      "role": "button",
      "name": "Sign in",
      "bounds": {"x": 96, "y": 1480, "width": 888, "height": 144}
    }
  ]
}
```

## Response

`found` tells you whether the model chose an element. When it did,
`element_id` is one of the IDs you sent. Argus checks the answer against your
request, so an ID you didn't send comes back as not found rather than as a
guess. `confidence` is the model's own estimate from 0 to 1.

```json
{
  "found": true,
  "element_id": "14",
  "confidence": 0.97,
  "model": "anthropic/claude-haiku-4.5",
  "cost_microdollars": 412,
  "prompt_tokens": 1210,
  "completion_tokens": 18,
  "latency_ms": 640
}
```

## Billing

Element locate is billed per token on the model it ran, the same way as
[Screenshots: locate](/api-reference/argus/screenshots-locate). Usage rows
label it with the endpoint `element_locate`. See [Usage](/usage/overview#inference-usage).

Errors use the [problem details](/reference/errors#problem-details) shape.
