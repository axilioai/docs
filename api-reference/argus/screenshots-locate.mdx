Find the element a natural-language query describes, such as
`"the blue Continue button"`, in a screenshot you supply. A vision-language
model reads the image and answers in one of two ways when `found` is true:

- **A box.** `bbox` is the element's pixel box in the screenshot.
- **A matched text.** When you send `texts`, the OCR results for the same
  screenshot, the model can answer with `matched_text_index` instead. It points
  into your `texts` list, so you reuse that entry's exact box.

Argus does not run OCR for this operation. To ground answers in text, call
[Screenshots: detect](/api-reference/argus/screenshots-detect) first and pass
its text results as `texts` unchanged: detect already returns each text box
normalized to `[0, 1]` of the image, which is the form `texts` takes. Only the
answer's `bbox` is in pixels.

Pass a `model` from [Models: list](/api-reference/argus/list-models), or omit
it to use the default. The call is billed per token on that model, and the
response reports `prompt_tokens`, `completion_tokens`, and `cost_microdollars`.

If you already have the screen's UI elements, for example from a DOM, use
[Elements: locate](/api-reference/argus/elements-locate) instead. It answers
with one of your elements, which is exact where a box is approximate.

Errors use the [problem details](/reference/errors#problem-details) shape.
