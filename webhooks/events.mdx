Each event describes one change to one resource. Its `type` names the resource
and what happened to it, like `run.failed` or `phone.online`. The body's `data`
is a snapshot of that resource. It uses the same field names and formats as the
API, but carries only the fields listed for each event: never your own content
(variables, names, tags), files or download links. See
[Webhooks](/webhooks/overview) for the request format, signatures and delivery
guarantees.

<Info>
  You can send every type below from the dashboard with **Test** on a
  destination's page. A test carries the example payload shown here and
  `"test": true`.
</Info>

## Recognising duplicates

The body's `id` (and the `webhook-id` header) is the same every time one change
reaches you, so you can skip an `id` you have already handled. Axilio builds it
from the event type and the resource:

| Events | `id` |
|---|---|
| `run.*`, `session.*`, `phone.rental.activated`, `phone.rental.canceled`, `subscription.canceled` | `<type>:<resource id>`. These happen once per resource. |
| `phone.maintenance_*`, `phone.offline`, `phone.online`, `phone.rental.past_due`, `subscription.updated` | `<type>:<resource id>:<time of the change>`. These can happen many times. |
| `invoice.paid`, `auto_recharge.*` | `<type>:<Stripe invoice id>` |
| `invoice.payment_failed` | `<type>:<Stripe invoice id>:<attempt number>` |
| `balance.*` | `<type>:<alert id>`. A new alert opens each time the balance drops again. |
| `file.*` | `<type>:<file or delivery id>` |

## Runs

| Event | Fires when |
|---|---|
| `run.started` | A queued run gets a phone and starts executing. |
| `run.completed` | A run finishes successfully. |
| `run.failed` | A run fails while executing, or Axilio could not queue or dispatch it. Fetch the run for its error message. |
| `run.cancelled` | A run stops before it finishes. `reason` is `user` (you cancelled it) or `queue_timeout` (it waited longer than its start timeout for a phone). |

`data` carries these fields of the [run](/api-reference/rest/runs/get-a-run):
`id`, `workflow_id`, `phone_id`, `session_id`, `status`, `trigger`,
`started_at`, `completed_at`, `canceled_at`, `success` and `created_at`. A field
with no value yet is left out. `run.cancelled` adds `reason`. Fetch the run for
anything else, such as its variables, error message or recording.

```json
{
  "id": "run.cancelled:0199a3c2-58c1-7f3a-9f2e-2f9a6a2f6a11",
  "type": "run.cancelled",
  "occurred_at": "2026-09-24T12:00:05Z",
  "test": false,
  "data": {
    "id": "0199a3c2-58c1-7f3a-9f2e-2f9a6a2f6a11",
    "workflow_id": "0199a3c2-58c1-7f3a-9f2e-2f9a6a2f6a22",
    "status": "cancelled",
    "trigger": "api",
    "canceled_at": "2026-09-24T12:00:05Z",
    "created_at": "2026-09-24T11:59:57Z",
    "reason": "user"
  }
}
```

## Sessions

| Event | Fires when |
|---|---|
| `session.started` | A session gets a phone and goes live. |
| `session.ended` | A session ends and Axilio releases its phone. `end_reason` says why. |
| `session.recording_ready` | The session's recording finishes uploading and you can download it. |

`end_reason` is one of:

- **`released`**: you released the session, or Axilio released it for you (a
  connection that never finished setting up, or maintenance on the rack).
- **`idle_timeout`**: no one used the session for longer than its
  [idle timeout](/devices/timeouts).
- **`max_duration`**: the session reached the maximum session length.
- **`run_finished`**: the run that the session served finished.
- **`phone_lost`**: the phone stopped answering during the session.

`data` for `session.started` and `session.ended` carries these fields of the
[session](/devices/timeouts): `session_id`, `status`, `source`, `phone_id`,
`workflow_id`, `allocated_at`, `deallocated_at` and `is_dedicated_phone`. A
field with no value yet is left out. `session.recording_ready` carries
`session_id` and `phone_id`; fetch the recording with
`GET /phones/sessions/{session_id}/recording`.

```json
{
  "id": "session.ended:0199a3c2-58c1-7f3a-9f2e-2f9a6a2f6a33",
  "type": "session.ended",
  "occurred_at": "2026-09-24T12:05:00Z",
  "test": false,
  "data": {
    "session_id": "0199a3c2-58c1-7f3a-9f2e-2f9a6a2f6a33",
    "status": "completed",
    "source": "interactive",
    "phone_id": "k3Vq8ZrT2mXa",
    "allocated_at": "2026-09-24T12:00:00Z",
    "deallocated_at": "2026-09-24T12:05:00Z",
    "is_dedicated_phone": false,
    "end_reason": "idle_timeout"
  }
}
```

## Billing

| Event | Fires when |
|---|---|
| `balance.low` | Your balance drops below the low-balance alert threshold you set. |
| `balance.depleted` | Your balance goes below zero. |
| `balance.recovered` | A balance alert ends because the balance rose back above its threshold. Turning an alert off does not send this. |
| `invoice.paid` | You pay a subscription or rental invoice. |
| `invoice.payment_failed` | A payment attempt on a subscription or rental invoice fails. Each attempt is its own event. |
| `subscription.updated` | Your plan subscription changes status, for example to `past_due` or back to `active`. |
| `subscription.canceled` | Your plan subscription ends. |
| `auto_recharge.succeeded` | Axilio charges an automatic top-up and credits your balance. |
| `auto_recharge.failed` | An automatic top-up fails. Axilio turns auto-recharge off until you turn it back on. |

Amounts use the same units as the [billing API](/billing/balance-and-invoices):
balances in microdollars with a formatted `balance_display`, invoices in cents.

```json
{
  "id": "balance.low:0199a3c2-9a0b-7c1d-8e2f-3a4b5c6d7e8f",
  "type": "balance.low",
  "occurred_at": "2026-09-24T12:00:00Z",
  "test": false,
  "data": {
    "alert_id": "0199a3c2-9a0b-7c1d-8e2f-3a4b5c6d7e8f",
    "kind": "low_balance",
    "threshold_microdollars": 5000000,
    "balance_microdollars": 3200000,
    "balance_display": "$3.20"
  }
}
```

## Files

| Event | Fires when |
|---|---|
| `file.ready` | An upload completes, or a file a phone captured during a session lands in your library. `source` is `upload` or `capture`. |
| `file.capture_failed` | A file a phone captured never became a library file. `reason` says why, for example that it was over the size limit or your storage quota. |
| `file.delivered` | A file you pushed to a phone arrived on it. |
| `file.delivery_failed` | A file you pushed to a phone did not arrive. `error` says why. |

`file.ready` and `file.capture_failed` carry the file's `id`, `filename`,
`mime_type`, `size_bytes` and, for a capture, `session_id`. `file.ready` adds
`source`; `file.capture_failed` adds `reason`. The delivery events carry the
[delivery](/files/move-files): `id`, `file_id`, `phone_id`, `filename`,
`mime_type`, `size_bytes`, `status`, `bytes_transferred`, `error` and
`created_at`. No event contains the file itself or a download link; list the
file through the API to get one.

## Phones

Axilio sends these events only for phones your organization
[rents](/devices/dedicated). Shared phones never send them.

| Event | Fires when |
|---|---|
| `phone.maintenance_started` | The phone leaves service for an automatic repair or a software update. |
| `phone.maintenance_ended` | The repair or update finished and the phone is back. |
| `phone.offline` | The phone leaves service until it proves healthy again or an Axilio operator repairs it. |
| `phone.online` | A phone that was out of service is back. |
| `phone.rental.activated` | A rental starts and the phone becomes yours alone. |
| `phone.rental.past_due` | A rental payment fails. The phone stays yours while Stripe retries the payment. |
| `phone.rental.canceled` | A rental subscription ends. Axilio releases the phone once no session is running on it. |

`reason` on the maintenance and offline events is one of `hardware`, `update`,
`unresponsive` or `operator`. The rental events carry the rental as
`GET /billing/phone-rental-subscriptions` returns it.

```json
{
  "id": "phone.offline:k3Vq8ZrT2mXa:1790251200000000",
  "type": "phone.offline",
  "occurred_at": "2026-09-24T12:00:00Z",
  "test": false,
  "data": {
    "phone_id": "k3Vq8ZrT2mXa",
    "phone_name": "Pixel 9 #14",
    "nickname": "checkout-bot",
    "status": "out_of_service",
    "reason": "unresponsive",
    "changed_at": "2026-09-24T12:00:00Z"
```
