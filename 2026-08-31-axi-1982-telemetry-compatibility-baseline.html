Audience

Backend, Python SDK, Go SDK, docs, release reviewers, and LLM agents validating AXI-1982 in dev or staging.

AXI-1982 Telemetry compatibility baseline

Accept the cost-map payload already on the wire, and make future frame kinds survivable before a third kind is deployed.

Implemented locally — executable post-deploy gate added · 2026-09-01 · AXI-1982

One-line summary
Make the two cost maps nullable in OpenAPI and ergonomic in Python, then add one narrow Python decoding fallback so a page containing a future frame kind remains usable instead of failing as a whole.

Executive Summary

Decision. AXI-1982 will establish a compatibility baseline, not redesign the frame model. The backend keeps its current retention-expired wire payload: sdk_call_costs: null and inference_costs: null. OpenAPI will declare those required properties nullable, the Python SDK will regenerate them as optional maps, and the high-level Trace helper will coalesce None to {}. Separately, the Python generated response union will receive a narrowly scoped, regeneration-safe unknown-kind fallback. Go already preserves unknown discriminants as raw JSON and only needs a regression gate.

Why both changes belong in the minimal ticket. Null cost maps cause a failure customers can trigger today. Unknown kinds are the deployment constraint raised in review: without a tolerant baseline, adding a future metric frame can make an otherwise valid retained page unusable in Python. Fixing only nullability removes the present parser error but leaves backend and SDK releases coupled for every future frame kind.

What “backend before SDK” means. This ticket must release one foundational tolerant SDK first. After customers are on that baseline, the backend may emit metric before an SDK release that adds a typed MetricFrame; the baseline SDK exposes it as unknown/raw. This ticket cannot retroactively change old strict SDK installations. Protecting every historical client would require server-side capability negotiation or filtering, which is intentionally outside this slice.

This boundary is deliberate. “Unknown” means a future discriminator, not malformed JSON. The Python fallback therefore cannot hide a malformed known frame. AXI-1982 does not add stricter validation to Go because that would be a separate generated-SDK behavior change; the post-deploy probe records the current behavior so reviewers do not infer a guarantee that does not exist.

Implementation Approach

1. Tell the truth about nullable cost maps

In backend/internal/routers/run/frames.go, annotate SDKCallCosts and InferenceCosts as nullable while keeping them required and removing neither JSON property. Huma already uses nullable:"false" tags elsewhere in the monorepo, so this must be expressed at the source struct rather than by editing a checked-in generated spec. The emitted OpenAPI 3.1 shape should become:

"sdk_call_costs": {
  "type": ["object", "null"],
  "additionalProperties": {"type": "integer", "format": "int64"}
}

Do not initialize the retention branch to empty maps in this solution. Raw API clients continue to see the exact state the backend emits: “cost lookup was not performed because the trace was withheld.” This is the cofounder’s proposed wire contract, made machine-readable.

2. Regenerate Python and normalize only at the ergonomic boundary

Regenerate with the pinned Fern Python generator 5.15.0. The two response fields must become required-but-nullable Python values, conceptually Optional[Dict[str, int]]. Then change SessionTelemetry.trace() so its accumulators merge page.sdk_call_costs or {} and page.inference_costs or {}. The raw generated response remains truthful; the high-level Trace remains convenient and stable.

# Raw response: preserves the wire
page.sdk_call_costs is None

# High-level result: stable collection contract
trace.sdk_call_costs == {}
trace.inference_costs == {}

3. Add a Python unknown-kind fallback without weakening all validation

Keep the OpenAPI frame union focused on the variants the server understands today: span and log. Do not add a fake discriminator mapping for arbitrary future values; OpenAPI discriminator mappings are concrete, and a nominal UnknownFrame mapping does not catch metric. Instead, add a deterministic post-generation step in platform-python that changes only RunSessionFramesResponseFramesItem:

  • Generate the normal Log and Span classes from OpenAPI.
  • Append a small ..._Unknown model with kind: str, extra fields allowed, and a validator that rejects the known values span and log.
  • Replace the discriminated two-member alias with an ordered plain union: Log | Span | Unknown.
  • Expose a raw view that serializes the unknown model back to the same JSON fields, and route it into the existing public platform.UnknownFrame in SessionTelemetry.trace().
  • Support Pydantic v1 and v2 using the compatibility helpers already shipped by the SDK.

The unknown validator is load-bearing. Without it, a malformed object claiming kind:"span" could fail the real span model and then be accepted by the generic fallback. The fallback must accept only values outside the known set.

4. Make the post-generation exception safe

Add a platform-python script such as scripts/patch_generated_frames.py and call it immediately after fern generate in the local/CI regeneration path. It must:

  • match the exact generated union declaration and fail with a useful message if Fern changes the file shape;
  • be idempotent, so running it twice produces no diff;
  • touch only the frame-item module and, if necessary, its public export list;
  • leave known generated model fields entirely generator-owned;
  • have a clean-regeneration test that runs Fern, applies the patch, and requires git diff --exit-code.

This is preferable to adding the whole generated model file to .fernignore. Ignoring the file would duplicate every known span/log field by hand and allow future schema additions to drift silently. A small, fail-closed transformation owns only the one behavior Fern cannot currently express for Python.

5. Prove Go instead of redesigning it

Regenerate Go from the nullable spec into its throwaway .gen directory and inspect the public diff before release. Go maps already represent JSON null as nil, and the current generated union preserves an unknown discriminant as raw JSON. Add an endpoint-response fixture containing span, metric, log so the behavior is protected at the page level, not only at the union helper level. If nullable OpenAPI unexpectedly changes a public Go accessor or field shape, stop and review that generated diff rather than accepting it as incidental churn.

Release Sequence

The order is the compatibility mechanism. The backend need not wait for a typed SDK release for every future kind, but it must wait once for the tolerant baseline.

1. Merge nullable OpenAPI + Python/Go tolerance tests
                ↓
2. Publish tolerant baseline SDK versions
                ↓
3. Document / observe adoption; set the supported minimum
                ↓
4. Future backend may emit kind="metric"
                ↓
5. Later SDK adds typed MetricFrame (optional for correctness)
  • Backend API version: implemented as 0.85.0, the next minor from the inspected 0.84.1 merge base.
  • Python package: implemented as 0.20.0 because public annotations change and unknown response behavior becomes observable.
  • Go package: remains 0.12.0; the runtime already accepted null maps and unknown discriminants, so this slice adds spec synchronization and regression coverage without manufacturing a new public type.
  • Rollback: no data migration exists. The backend spec change can be reverted before a third kind ships. A published SDK should be forward-fixed rather than unpublished. A future kind can be disabled at its producer if adoption proves insufficient.
Old clients remain old
An installed Python version from before this baseline still fails on null maps and future kinds. If product policy requires a future backend kind to be safe for those versions too, AXI-1982 must expand to server-side negotiation/filtering or revert to the backend {} normalization for the cost-map failure.

Risks and Trade-offs

  • The fix depends on SDK adoption. The cost parser failure is not fixed for already-installed Python clients. Mitigation: publish and document a clear minimum version; consider the backend {} fallback if retention reads cannot require upgrades.
  • Post-generation code is maintenance. A Fern output change can break the transformation. Mitigation: exact anchors, idempotency, a clean-regeneration CI gate, and no ownership of generated span/log fields.
  • An undiscriminated union performs more validation work. Python tries known candidates before the fallback. At the endpoint’s maximum page size of 1,000 and only three members, the expected cost is small; add a fixture benchmark only if tests show material latency.
  • A permissive fallback could hide server bugs. The explicit “unknown kind only” validator prevents malformed span/log objects from falling through. Missing or non-string kinds remain errors.
  • Raw and high-level cost semantics differ. Raw Python exposes None; Trace exposes {}. Mitigation: document the boundary and test it. retention_expired remains the authoritative reason.
  • OpenAPI still cannot promise the SDK’s runtime catch-all structurally. The spec enumerates known server variants, while first-party SDKs implement tolerant reading. Third-party generated clients may remain closed. The raw API docs must continue telling customers to build tolerant readers.
  • Go regeneration may react to nullable maps. Treat any pointer/accessor churn as a design review, not an automatic generated diff. Go already parses null maps without a schema change to its runtime representation.
  • The baseline does not authorize a third kind. It removes a technical coupling for supported SDK versions; it does not decide the product semantics, storage, docs, or rollout of metric.

Post-deployment Agent Test Plan

Decision
Validate the deployed backend with read-only requests, and validate forward-compatible SDK behavior with a local capture/replay server using the exact candidate SDK artifacts. Do not deploy a fake third frame kind, change an organization’s retention policy, edit session timestamps by hand, or use customer sessions merely to make the test possible.

This runbook is designed for an LLM agent after the candidate backend reaches dev or staging and the candidate SDK artifacts are available. It produces a machine-readable result and a small redacted evidence bundle. It is intentionally stricter than a manual smoke test: a retry that passes is reported as flaky, a missing fixture is reported as blocked rather than green, and every assertion has a stable test ID.

Implemented entry point
Dispatch axilio/.github/workflows/telemetry_compat_postdeploy.yml with the target, exact backend deploy SHA, exact platform-python ref, and exact platform-go ref. The workflow refuses production, converges the dedicated fixture, runs the raw validator, builds both candidate SDK artifacts, executes Python under Pydantic 1 and 2, executes Go, and uploads the redacted evidence bundle for 30 days. An LLM agent may dispatch and inspect this workflow; it should not reimplement the assertions ad hoc.

Out of Scope
